# StudyQuest

A revision web app for GCSE and A-level students that works like a ranked game. You revise with flashcards and quizzes, earn Study Coins for work the server can verify, and play timed 1v1 quiz battles against other students on an Elo ladder.

Built with Next.js, React, TypeScript, PostgreSQL and Prisma, with AI assistance from Claude Code.

## Features

### Ranked 1v1 battles

- **Two-minute head-to-head battles.** Both players get the same questions in the same order, dealt from a shared question bank.
- **Elo rating with eleven ranks**, from Student up to Transcendent.
- **Matchmaking by rank and rating.** It pairs you with the closest-rated opponent, and widens the rank range the longer you wait.
- **Scoring that rewards speed and accuracy.** Only correct answers earn points, and the total is scaled by how reliable you were, so guessing loses.
- **Global and regional leaderboards.**
- **A character and cosmetics shop**, where you spend the coins you earn.

### Question bank

- **Six subjects:** Maths, Further Maths, Physics, Chemistry, Biology and Computer Science, at GCSE and A-level.
- **Generated by code.** Each generator builds questions from a seed and re-checks its own answer a second way before the question can be stored.
- **Tagged with a fixed vocabulary** of subject, topic, year group and difficulty, so players can choose what they are tested on.

### Revision tools

- **Flashcards** with a Smart Mode that schedules each card by adaptive spaced repetition, and a Cram Mode for last-minute revision.
- **Quizzes** with multiple-choice and written questions, mark schemes and a server-issued timer.
- **AI marking** of written answers, which you can override.
- **PDF to quiz:** upload a PDF and get a quiz built from it.
- **Test feedback:** upload a marked test and get strengths, weaknesses and a topic breakdown.
- **Daily quiz and streaks**, with a streak multiplier that climbs to ×5.
- **Communities** for sharing sets and quizzes with a class, with public, invite-only and private access.

### Study Coins

Coins are earned from active time on the app, verified study time, the daily quiz, finishing flashcard sets, quiz scores and battles. Every rule and number lives in `src/lib/coins/rules.ts`.

## Getting started

You need Node.js 20.11 or later and a PostgreSQL database you can write to.

```bash
# 1. Install
git clone https://github.com/ezawn/ranked-study-app.git
cd ranked-study-app
npm install

# 2. Configure
cp .env.example .env
#    Set DATABASE_URL to your Postgres database.
#    Generate an auth secret with: npx auth secret

# 3. Create the tables and seed the data
npm run db:push
npm run db:seed
npm run db:seed:cosmetics
npm run seed:bank

# 4. Run
npm run dev
```

Then open <http://localhost:3000>.

Use `npm run db:push` to change the schema, not `prisma migrate dev`. The project has no migration history, so `migrate dev` will offer to reset the database.

### Optional setup

- **Google sign-in:** set `AUTH_GOOGLE_ID` and `AUTH_GOOGLE_SECRET`, with `http://localhost:3000/api/auth/callback/google` as the redirect URI.
- **Real AI:** the app runs without an API key, using a local mock provider. To use Claude, set `AI_PROVIDER=anthropic` and `ANTHROPIC_API_KEY`.
- **Email:** password reset links are printed to the server console unless you set `RESEND_API_KEY` and `MAIL_FROM`.
- **Background worker:** `npm run worker` retries failed AI marking and closes abandoned quiz attempts. A cron job calling `GET /api/cron/run` with `Authorization: Bearer $CRON_SECRET` does the same job.

## How it works

### The server decides everything

The browser never decides a score, a deadline or a reward.

- **Answers are marked on the server.** Correct answers are stripped from everything sent to the browser during a quiz or battle.
- **Deadlines are stored on the server.** The countdown on screen is only a display, and answers that arrive late are refused.
- **Coins move in one place.** `awardCoins()` in `src/server/services/coins.ts` is the only function that changes a balance.
- **Every award is a ledger row with a unique key**, so submitting twice pays once.
- **Study time is measured, not reported.** The server works out elapsed time from its own clock and caps each heartbeat, so replaying a request earns nothing.
- **Daily limits are read from the database**, never from the request.

### Battles

1. A player picks subjects and joins the queue.
2. The matchmaker pairs them with the closest-rated player in their rank window.
3. The server deals one set of questions from the bank and stores it on the match, so both players see the same hand.
4. Each answer is marked on the server as it arrives, and each client polls for the opponent's progress.
5. After two minutes the server scores both players and updates their Elo.

The Elo system is standard, with two changes: a heavy underdog loses very little for a loss, and every win or loss moves the rating by at least one point.

### Spaced repetition

Each card has a base interval that depends on your answer: 24 hours for Don't Know, 48 for Partially Know and 120 for Know. A per-card ease factor and a streak of correct answers stretch or shrink that interval over time. A card you keep failing is brought back after 12 hours. Cram Mode sessions are recorded but never change the Smart Mode schedule.

### Code layout

```
prisma/            Database schema and seed scripts
scripts/           Background worker and a standalone logic check
src/
  app/             Pages and API routes (Next.js App Router)
  components/      React components, grouped by feature
  lib/             Pure logic with no database access
    arena/           Elo, ranks, matchmaking and battle scoring
    bank/            Question generators, taxonomy and selection
    coins/           Coin rules
    srs/             Spaced repetition scheduler
    quiz/            Quiz marking
    ai/              Claude and mock AI providers
  server/
    actions/       Server actions that validate input and apply rate limits
    services/      Business logic and database transactions
    jobs/          Background jobs
tests/             Vitest test suite
```

Pages and components never touch the database. They call server actions, which validate input with Zod and pass the work to services. The rules themselves sit in `src/lib` as pure functions, which is what makes them testable without a database.

## Testing

```bash
npm test              # Run the Vitest suite
npm run verify:logic  # Check the same rules without a test framework
npm run typecheck     # Type-check the project
```

There are over 250 test cases across eight files, covering the arena, the question bank, the coin rules, quiz marking, spaced repetition and day boundaries. `tests/anti-cheat.test.ts` is written as a set of attacks, such as farming the timer or beating the clock, and checks that each one fails.

The tests cover the pure logic. They do not cover database transactions or authorisation checks, which need a live database.

## Limitations and next steps

- **No payments.** A user's plan controls every limit, but there is no payment provider. A development-only switch in Settings changes the plan.
- **Cosmetics have no artwork.** Every item is drawn as a labelled placeholder.
- **Community Wars is not built.** The page is a placeholder.
- **File storage is local only.** Uploads are written to disk, and the S3 driver is a stub.
- **Uploads are PDF only.** Photos of a paper would need OCR first.
- **No email verification** on sign-up.
- **Rate limiting is in-process**, so it only works with a single server.
- **Battles use polling.** Moving to WebSockets would make the opponent's progress update instantly.
